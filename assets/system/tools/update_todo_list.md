### update_todo_list

**描述：**
将整个TODO列表替换为反映当前状态的更新检查表。始终提供完整列表；系统将覆盖前一个列表。此工具专为逐步任务跟踪而设计，允许您在更新前确认每个步骤的完成情况，一次性更新多个任务状态（例如标记一个为已完成并开始下一个），并在长时间或复杂任务中动态添加新待办事项。

**检查表格式：**
- 使用单层markdown检查表（无嵌套或子任务）。
- 按照预期执行顺序列出待办事项。
- 状态选项：
	 - [ ] 任务描述（待处理）
	 - [x] 任务描述（已完成）
	 - [-] 任务描述（进行中）

**状态规则：**
- [ ] = 待处理（未开始）
- [x] = 已完成（完全结束，无未解决的问题）
- [-] = 进行中（当前正在进行）

**核心原则：**
- 更新前，始终确认自上次更新以来已完成的待办事项。
- 您可以在一次更新中更新多个状态（例如，将前一个标记为已完成，将下一个标记为进行中）。
- 当在长时间或复杂任务期间发现新的可操作项目时，立即将其添加到待办列表中。
- 除非明确指示，否则不要删除任何未完成的待办事项。
- 始终保留所有未完成的任务，并根据需要更新其状态。
- 只有当任务完全完成时才标记为已完成（无部分完成，无未解决的依赖项）。
- 如果任务被阻塞，保持其为进行中状态，并添加一个新的待办事项描述需要解决的问题。
- 仅当任务不再相关或用户要求删除时才删除任务。

**使用示例：**
<update_todo_list>
<todos>
[x] 分析需求
[x] 设计架构
[-] 实现核心逻辑
[ ] 编写测试
[ ] 更新文档
</todos>
</update_todo_list>

*在完成"实现核心逻辑"并开始"编写测试"后：*
<update_todo_list>
<todos>
[x] 分析需求
[x] 设计架构
[x] 实现核心逻辑
[-] 编写测试
[ ] 更新文档
[ ] 添加性能基准测试
</todos>
</update_todo_list>

**何时使用：**
- 任务复杂或涉及多个步骤或需要持续跟踪。
- 您需要一次性更新多个待办事项状态。
- 在任务执行过程中发现新的可操作项目。
- 用户请求待办列表或提供多个任务。
- 任务复杂且受益于清晰的逐步进度跟踪。

**何时不使用：**
- 只有一个简单任务。
- 任务可以在一两个简单步骤中完成。
- 请求纯粹是对话式或信息性的。

**任务管理指南：**
- 在当前任务的所有工作完成后立即标记为已完成。
- 通过标记为进行中来开始下一个任务。
- 一旦识别出新待办事项就立即添加。
- 使用清晰、描述性的任务名称。
