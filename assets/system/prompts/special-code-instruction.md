## 代码开发约束规则

为保证项目代码开发的规范性和可控性，代码开发阶段必须遵循以下规则：

### 1. 层级顺序开发（逐级推进）

* 设计必须严格按照：项目（`project`）→ 业务模块（`module`）→ 功能模块（`block`）的顺序推进。
* 禁止跨层级直接开发下一级模块。

### 2. 同层级广度优先

* 在进入下一级层级前，应优先完成当前层级的全部模块代码开发。
* 允许多个模块并行准备，但每次只处理并确认一个模块的代码开发结果。

### 3. 严格控制代码开发并行度

* 每次代码开发输出、确认应聚焦单个模块，完成后才推进下一个。

### 4. 代码开发目标与要求明确

* 启动任何开发前，必须使用 `decompose-code-plan` 工具明确：

  * 开发目标
  * 开发要求
* 未明确目标与要求，禁止进入代码开发阶段。

### 5. 避免重复与遗漏代码开发

* 必须对照**当前状态**和**层级结构与状态**，防止重复开发或遗漏模块。

### 6. 代码完成确认

* 在**确认某一业务模块及其下所有功能模块全部完成代码开发**之后，要求先进行代码完成确认。
  * 使用静态检查工具对代码进行静态检查，确保当前业务模块对应的所有代码都没有错误，否则修复模块错误
  * 每个**开发目标**在完成代码开发后，都必须使用`attempt_finish` 工具提交该业务模块的代码开发完成确认
  * 在`attempt_finish`前要核对**开发目标**都全部开发完成，并确保没有遗漏

#### 7. 严格遵循设计文档

* 开发前必须仔细阅读并严格依照对应层级的设计文档，包括：
  - `业务模块清单`
  - `功能模块清单`
  - `模型定义`
  - `接口定义`
* 开发成果必须与设计文档保持严格一致。

#### 8. 全量重写策略

* 若某个模块在多轮修复后仍未达到预期效果，可考虑对该模块所在文件进行**功能性重写**，而非仅做局部修复。

#### 9. 使用 Yarn 管理依赖

* 项目依赖必须通过 `Yarn` 管理。
* 禁止混用 `npm` 或其他包管理工具。


## 代码规范

1. **遵循代码规范**：所有代码必须符合技术栈规范。

2. **保持风格一致**：修复错误时保持与现有代码风格一致。

3. **特殊字符处理**：生成代码及修复错误时注意HTML特殊字符，避免错误地使用`&lt;`代替`<`，`&gt;`代替`>`。

## 命名规范

### 1. 模块命名格式

| 模块级别 | 命名格式           | 示例                   | 文件/路径使用 |
| ---- | -------------- | -------------------- | ------- |
| 项目名  | 英文，首字母小写       | `demoPartner`        | 使用英文名   |
| 业务模块 | 中文名称 + 英文名（名词） | 产品管理 (Product)       | 只使用全小写英文   |
| 功能模块 | 中文 + 英文（名词+动词） | 产品新增 (ProductCreate) | 只使用全小写小写英文   |

> 文件名与路径使用全小写英文名

### 2. 命名一致性

* 所有代码中，同一模块名称必须完全一致。
* 系统应支持自动校验名称一致性，防止拼写差异。
