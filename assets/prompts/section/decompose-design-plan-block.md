### 分解约束  
1. **原子化拆分**  
   - 功能点需为最小可执行单元（如筛选功能拆解为`条件输入`、`筛选按钮触发`）。  
   - 禁止合并多个独立功能到同一功能点。  

2. **数据定义清晰**  
   - 明确接口字段及其类型（如筛选条件：`keyword: string`，`filters: Filter[]`）。  
   - 定义响应数据结构及其用途（如筛选结果：`{ total: number, items: DataItem[] }`）。  

3. **交互逻辑透明**  
   - 描述功能点间调用及依赖关系（如筛选结果影响表格渲染内容）。  
   - 标注事件触发及响应机制（如条件更改时触发`onFilterChange`事件）。  

4. **输出规范**  
   - 生成文件：`{业务模块名}/{功能块名}/{功能点名}-功能点设计.md`  
   - 文件内容必须包含：  
     - 功能点名称  
     - 功能描述  
     - 数据结构（请求/响应）  
     - 交互流程  
     - 依赖说明  

### 分解步骤  
1. **识别子功能点**  
   - 按功能块职责拆分为核心动作（如商品管理模块拆分为`商品列表展示`、`新增商品`、`筛选功能`）。  

2. **定义功能点元数据**  
   功能点名：功能点名称  
   描述：功能点描述。  
   数据结构：  
   - 请求参数  
   - 响应参数

   依赖说明：功能点依赖的模块和资源清单  

3. **生成设计文档**

   * 按规范输出到功能块目录：`{业务模块名}/{功能块名}/{功能点名}-功能点设计.md`

```plaintext
// 筛选功能-功能点设计.md
### 功能点名称  
筛选功能  

### 功能描述  
实现商品列表的筛选功能，支持关键字搜索及多条件筛选。  

### 数据结构  
**请求参数**  
{
  "keyword": "电子",
  "filters": [
    { "type": "category", "value": "手机" },
    { "type": "priceRange", "value": "1000-2000" }
  ]
}

**响应参数**  
{
  "total": 50,
  "items": [
    { "id": 1, "name": "智能手机A", "price": 1200 },
    { "id": 2, "name": "智能手机B", "price": 1500 }
  ]
}

### 交互流程  
1. 用户输入关键字后触发筛选请求，更新筛选条件并调用筛选接口。  
2. 用户选择筛选条件（如分类、价格区间），实时更新筛选条件并重新加载数据。  
3. 数据返回后，更新商品列表内容及总数展示。  

### 依赖说明  
- 依赖接口：`/api/products/filter`  
- 依赖组件：  
  - `FilterInput`（输入组件）  
  - `FilterDropdown`（下拉选择组件）  
  - `Table`（商品列表渲染组件）  
```
